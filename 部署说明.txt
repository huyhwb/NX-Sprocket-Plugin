================================================================
  NX 12.0 链轮插件 —— 复制到其他电脑 操作说明
  适用插件版本：v22（2026-10-05）
================================================================

【三行速查】
  1) 把 startup\ 和 application\ 两个目录，连同启动器一起复制到目标电脑
  2) 双击「启动NX链轮插件.bat」；或设系统环境变量 UGII_USER_DIR = 插件目录
  3) 打开 NX → 菜单「链轮工具 → Generate Sprocket...」


一、目标电脑需要什么
----------------------------------------------------------------
1. 已安装 Siemens NX 12.0，且版本与源电脑一致（本插件按 NX 12.0 的
   NXOpen API 开发，其他版本未做验证）。
   判断方法：目标机存在 NXBIN\ugraf.exe，例如
     C:\Program Files\Siemens\NX 12.0\NXBIN\ugraf.exe
2. Windows 64 位。
3. 不需要 Visual Studio、不需要 .NET SDK、不需要任何编译步骤。
   本插件是「.vb Journal + .dlx 对话框」，由 NX 在运行时自行加载执行。


二、要复制的文件（只有这些）
----------------------------------------------------------------
插件目录（下面叫 <插件目录>；放哪个盘、路径含中文都没关系）：

  <插件目录>\
    |-- 部署说明.txt                本文件
    |-- 启动NX链轮插件.bat          启动器（自动查找 NX 安装位置）
    |-- 导出插件包.bat              可选：在源电脑上生成干净拷贝
    |-- startup\
    |     |-- SprocketPlugin.men    菜单定义（NX 启动时自动加载）
    |     |-- SprocketPlugin.vb     主程序（Journal，NX 运行时执行）
    |     |-- SprocketPlugin.dlx    对话框（备用查找位置）
    |     \-- sprocket_icon.bmp     菜单图标（必须与 .men 同目录）
    \-- application\
          |-- SprocketPlugin.dlx    对话框（首选查找位置）
          \-- SprocketPlugin.vb     主程序副本（保持与 startup 一致）

  【必须】startup\ 与 application\ 两个目录整体复制。
  【建议】README.md（功能与参数说明）、部署说明.txt（本文件）
  【可选】启动NX链轮插件.bat、推送到GitHub.bat、导出插件包.bat

  注：早期 C# 版本遗留的文件（*.cs、SprocketPlugin.csproj、
      dbc_udf_ascii.def、udf_database.txt、custom_dirs_README.txt）
      已从目录中清理，不需要再关心。

  提示：其实把整个文件夹原样拷过去也能用（多余文件不影响 NX），
        用「导出插件包.bat」只是为了得到一个干净的拷贝。


三、配置方法（二选一）
----------------------------------------------------------------
两种方法都围绕同一个环境变量：

    UGII_USER_DIR = <插件目录>

NX 启动时会在 $UGII_USER_DIR\startup\ 和 $UGII_USER_DIR\application\
里寻找菜单和对话框。

■ 方法A：用启动器（推荐，不改系统设置）
  1. 把插件目录整个复制到目标电脑，例如 D:\NX链轮插件
  2. 双击「启动NX链轮插件.bat」
     它会把 UGII_USER_DIR 指向自己所在目录，然后启动 NX。
  3. 如果提示找不到 ugraf.exe，用下面任一方式告诉它 NX 在哪：
     - 把 NX 的 ugraf.exe 直接拖到这个 .bat 上
     - 或在同目录建一个 nx_path.txt，第一行写 ugraf.exe 完整路径
     - 或手工编辑 .bat 里 set "NXEXE=..." 那一行

■ 方法B：设系统环境变量（永久生效，每次启动 NX 都带插件）
  1. 右键「此电脑」→ 属性 → 高级系统设置 → 环境变量
  2. 在「系统变量」中新建：
       变量名：UGII_USER_DIR
       变量值：<插件目录>      （例：D:\NX链轮插件，末尾不要加反斜杠）
  3. 确定后，彻底退出所有 NX 进程（任务管理器确认 ugraf.exe 已结束），
     再正常启动 NX 即可。

  ※ 重要：UGII_USER_DIR 只能有一个。
     如果目标电脑已有公司统一配置的这个变量（指向别的插件目录），
     不要再新建，而是把本插件 startup\ 和 application\ 里的文件
     合并进那个已存在的目录（只要文件名不冲突即可共存）。


四、确认安装成功
----------------------------------------------------------------
1. 启动 NX，新建或打开一个部件文件
2. 菜单栏应出现「链轮工具」（Sprocket Tool）
3. 点「链轮工具 → Generate Sprocket...」，应弹出「链轮生成器」对话框
4. 「链条规格」下拉可正常展开，共 14 项（05B ... 48A、自定义）


五、常见问题
----------------------------------------------------------------
1. 菜单栏没有「链轮工具」
   检查是不是 UGII_USER_DIR 没生效：
     - 变量值就是插件目录本身，不是它的子目录
     - 值末尾没有多余空格或反斜杠
     - 改完必须重启 NX（确认 ugraf.exe 已全部退出）
     - .men 确实在 <插件目录>\startup\ 下

2. 点菜单报「找不到 .dlx」或对话框打不开
   确认 <插件目录>\application\SprocketPlugin.dlx 存在。
   插件查找顺序：application → startup → 交给 NX 按标准路径搜索。

3. 菜单图标是空白方块
   确认 sprocket_icon.bmp 与 SprocketPlugin.men 同在 startup\ 目录下。

4. 双击 .bat 窗口一闪就没了
   说明没找到 NX、NX 没启动起来。请在命令行里运行它，就能看到提示文字。

5. 弹出「生成失败：...」信息框
   那是插件自身的诊断框（含 阶段 / 轮廓 / 探针 / 实体 四行），
   属于插件运行结果，不是安装问题。把全文反馈给开发方即可定位。

6. 想确认两台电脑上的是不是同一版本
   命令行执行：
     certutil -hashfile startup\SprocketPlugin.vb  MD5
     certutil -hashfile startup\SprocketPlugin.dlx MD5
   同一版本应满足：startup\ 与 application\ 里的同名文件哈希一致。

   当前版本（v22）指纹：
     SprocketPlugin.vb   5918ffd053505c18210b1c623fd52207
     SprocketPlugin.dlx  4098df04750c0ad790fc3a7fd7db66fb


六、日常更新插件
----------------------------------------------------------------
开发方给出新版 SprocketPlugin.vb / SprocketPlugin.dlx 后：
  1. 覆盖 <插件目录>\startup\ 下的同名文件
  2. 把同样两个文件复制到 <插件目录>\application\（保持两份一致）
  3. 关闭并重启 NX 生效

  .vb 与 .dlx 必须成对更新，不要只换其中一个。


七、把插件上传到 GitHub（可选）
----------------------------------------------------------------
本插件目录已经是一个 git 仓库（分支 main），首次提交里已包含全部
源文件，所以本地这一步不用再做了，直接看下面三步。

■ 第 1 步：在 GitHub 网页上新建一个空仓库
   - 打开 https://github.com/new
   - Repository name 填仓库名。中文名 GitHub 也接受，但克隆地址会
     变成一长串 %XX 转义，建议用 ASCII 名，例如 NX-Sprocket-Plugin
   - 三个初始化选项（Add a README file / .gitignore / license）
     一个都不要勾 —— 勾了远端就会先有提交，首次推送会报 rejected
   - 建好后复制仓库地址，形如：
       https://github.com/<你的用户名>/NX-Sprocket-Plugin.git

■ 第 2 步：让本地仓库指向它，推送一次
   在本插件目录打开 Git Bash（或命令行），执行：

       git remote add origin https://github.com/<你的用户名>/NX-Sprocket-Plugin.git
       git push -u origin main

   首次会要求登录 GitHub。GitHub 早已不支持账号密码，
   密码处要填 Personal Access Token（个人访问令牌）：
       https://github.com/settings/tokens
       → Generate new token (classic) → 勾选 repo → 生成
       → 复制那串字符，粘贴到密码提示处
   Windows 会把它记进「凭据管理器」，以后不用再输。

■ 第 3 步：以后每次更新
   双击「推送到GitHub.bat」，它会自动 add + commit + push。
   也可以手动执行：
       git add -A
       git commit -m "说明这次改了什么"
       git push

仓库约定（已配好，一般不用动）：
  - .gitignore     忽略 *.zip 与 _portable\（打包产物不进仓库）
  - .gitattributes 关闭换行符转换，保证 .bat/.dlx/.vb 字节原样
                   —— .bat 若被改成 LF，在 Windows 上会执行异常
  - 不要往仓库里放 NX 安装包、许可证文件等大文件

常见问题：
  1. push 报 "rejected / fetch first"
     远端仓库不是空的（建库时勾了 README）。执行下面任一方式：
       git pull --rebase origin main      然后再 push
       git push -u origin main --force    用本地覆盖远端

  2. push 报 CRYPT_E_NO_REVOCATION_CHECK 或
     "unable to get local issuer certificate"（证书类错误）
     这是本机在用 Watt Toolkit（原 Steam++）之类工具加速 GitHub，
     它用自签根证书做了 TLS 中间人，git 不认这张证书。
     正规修法：把它的根证书并入 git 的 CA 包。
     本机已完成，记录在此备查：
       C:\Users\<你>\.git-certs\git-ca-bundle.pem
       git config --global http.sslBackend openssl
       git config --global http.sslCAInfo C:\Users\<你>\.git-certs\git-ca-bundle.pem
     注意：该根证书有有效期（约 1 年）。若某天又开始报证书错误，
     在 Watt Toolkit 里重新安装证书后，照上面重建 CA 包即可。

  3. 确认远端与本地是同一版本
       git log --oneline -1          本地最新提交
       git ls-remote origin HEAD     远端最新提交
     两个哈希一致即同步完成。

其它用途：
  - 同步到另一台电脑：直接 git clone 仓库地址，比拷目录更省事
  - 只想发布可下载的压缩包：先用「导出插件包.bat」生成 _portable\，
    再到仓库页面的 Releases 里上传，比塞进仓库更合适
